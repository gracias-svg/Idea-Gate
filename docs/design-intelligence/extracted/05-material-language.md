# Purpose

Material is the physical expression of the interface.

Every surface should communicate its role before users interact with it.

The interface should feel crafted rather than assembled.

---

# Design Philosophy

IdeaGate should resemble a carefully engineered workspace.

Not a dashboard.

Not a website.

Not a marketing page.

Not a game.

Users should feel they are working inside a premium desktop application.

---

# Material Principles

## Principle 1

Depth communicates hierarchy.

Never create depth simply for aesthetics.

Depth exists only when it explains importance.

---

## Principle 2

Every surface must have a purpose.

Examples

Canvas

Primary work area

Panels

Supporting context

Dialogs

Focused interaction

Floating Elements

Temporary interaction

Notifications

Ephemeral information

Never invent new surface types without justification.

---

## Surface Hierarchy

# Border Philosophy

Borders should define separation.

Not decoration.

Prefer

Subtle contrast

Spacing

Depth

Instead of heavy outlines.

Avoid boxes inside boxes inside boxes.

---

# Elevation

Elevation should communicate interaction priority.

Higher elevation means

Higher attention.

Not stronger decoration.

Elevation should remain subtle.

---

# Corner Radius

Corners should create softness.

Not novelty.

Maintain one consistent radius system across the product.

Avoid mixing many radius values.

---

# Shadows

Shadows exist to communicate depth.

Avoid dramatic shadows.

Prefer soft ambient elevation.

If a shadow attracts attention by itself, it is too strong.

---

# Glass Effects

Glass should never become the design language.

If used

Use only for

Temporary overlays

Floating command palette

Spotlight interactions

Never for the primary workspace.

---

# Blur

Blur communicates focus.

Not decoration.

Use blur only when users should concentrate on a foreground task.

---

# Color Usage

Material should rely on structure more than color.

Color communicates

Status

Risk

Success

Selection

Never hierarchy.

Hierarchy comes from composition and typography.

---

# Surface Density

Allow breathing room.

Avoid tightly packed interfaces.

Users should feel calm during long sessions.

---

# Dividers

Prefer whitespace.

Use dividers only when separation cannot be understood through spacing.

---

# Icons

Icons support text.

Icons never replace meaning.

Avoid decorative icon collections.

Every icon should improve recognition speed.

---

# Buttons

Primary

One per context.

Secondary

Supporting actions.

Tertiary

Low emphasis.

Danger

Rare.

Buttons should communicate confidence without overwhelming the interface.

---

# Inputs

Inputs should disappear visually until interaction begins.

Avoid oversized borders.

Avoid unnecessary shadows.

Focus state should be unmistakable.

---

# Cards

Cards group information.

Cards should never become decoration.

Avoid nested cards.

Avoid card grids when a document layout is more appropriate.

---

# Workspace Canvas

The canvas should feel limitless.

Avoid excessive framing.

Users should focus on work, not containers.

---

# AI Panels

AI should appear as a collaborator.

Not an advertisement.

Not a chatbot widget.

The AI workspace should visually integrate into the product.

---

# Motion Relationship

Material and motion are inseparable.

Every elevation change should have a corresponding motion change.

Every overlay should animate consistently.

# Material Quality Checklist

Before approving any screen ask

[ ] Can users understand hierarchy without color?

[ ] Are surfaces purposeful?

[ ] Is elevation subtle?

[ ] Are borders minimal?

[ ] Does whitespace create grouping?

[ ] Do cards improve understanding?

[ ] Does the workspace feel premium?

---

# Non-Negotiables

Never decorate surfaces simply because space exists.

Never rely on borders to create hierarchy.

Never introduce visual effects that compete with the content.

Material exists to support thinking.
