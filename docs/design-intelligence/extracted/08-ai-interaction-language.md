# Purpose

AI should feel like a trusted product teammate.

Not an assistant.

Not a chatbot.

Not a search engine.

Not an autocomplete engine.

Users should feel that intelligent specialists are collaborating with them throughout the product lifecycle.

---

# Core Philosophy

AI exists to improve human thinking.

Not replace it.

The interface should always communicate

"I am helping you make better product decisions."

instead of

"I generated something."

---

# AI Personality

AI should feel

Calm

Confident

Transparent

Evidence-based

Structured

Collaborative

Professional

Never sarcastic.

Never overly enthusiastic.

Never anthropomorphize itself.

Never pretend certainty.

---

# AI Responsibilities

AI should

Generate

Review

Critique

Explain

Compare

Summarize

Validate

Recommend

Prioritize

Never make irreversible decisions automatically.

---

# Human Responsibilities

Humans always own

Approval

Strategy

Vision

Business decisions

Final prioritization

AI proposes.

Humans decide.

---

# AI Visibility

AI should remain visually integrated into the workspace.

Avoid separate chatbot windows.

Avoid floating chat bubbles.

Avoid "Ask AI" everywhere.

Instead,

AI should appear where work happens.

Examples

Inside documents

Inside reviews

Inside comparisons

Inside planning

Inside architecture

Inside UX

---

# Recommendation Pattern

Every recommendation should follow the same structure.

Recommendation

↓

Why

↓

Evidence

↓

Expected Impact

↓

Confidence

↓

Alternative Options

↓

Accept

↓

Modify

↓

Reject

Never show recommendations without reasoning.

---

# Confidence System

Every meaningful AI output should expose confidence.

Confidence should never exist alone.

Always explain

Why confidence is high or low.

Example

88%

Based on

14 research sources

3 similar artifacts

Complete lifecycle context

Never display arbitrary percentages.

---

# Explainability

Every AI decision should be explainable.

Users should always be able to ask

Why?

What changed?

What assumptions were made?

Which evidence supports this?

Explainability builds trust.

---

# Progressive AI

Do not overwhelm users.

Default

Summary

Expanded

Reasoning

Evidence

Alternatives

Technical Details

Users choose how deep they wish to explore.

---

# AI Streaming

Generated work should appear progressively.

Users should see work unfolding naturally.

Avoid

Long blank loading screens.

Prefer

Streaming

Incremental generation

Section-by-section completion

Progress indicators

---

# Multi-Agent Identity

IdeaGate is not powered by one AI.

Different specialists contribute.

Examples

Research Agent

UX Agent

Architecture Agent

QA Agent

Strategy Agent

Coordinator

Each specialist should have a clear responsibility.

Avoid making every response feel identical.

---

# AI Collaboration

AI should collaborate across agents.

Users should observe

Research influencing UX

Architecture influencing QA

QA influencing Planning

Coordinator validating all outputs

This reinforces the Product Operating System concept.

---

# Interruptions

AI should never interrupt users unnecessarily.

Avoid

Auto-opening dialogs

Forced suggestions

Unexpected popups

AI should wait until users request assistance or complete meaningful actions.

---

# AI Review Pattern

Generated Artifact

↓

AI Review

↓

Strengths

↓

Weaknesses

↓

Suggestions

↓

Risk Assessment

↓

Accept Improvements

Users should always understand the reasoning behind revisions.

---

# AI Critique

Criticism should be constructive.

Instead of

"This is wrong."

Prefer

"This section may benefit from..."

Explain the reasoning.

Offer alternatives.

---

# AI Memory

AI should remember

Current project

Current lifecycle stage

Recent decisions

Accepted recommendations

Rejected recommendations

Previous versions

Never ask users for information already available within the current project context.

---

# AI Context Awareness

Recommendations should consider

Lifecycle stage

Existing artifacts

Dependencies

Research

Architecture

Business goals

Never generate in isolation.

---

# AI Transparency

Whenever AI performs work users should understand

What is happening

Why it is happening

What information is being used

What assumptions exist

Transparency creates confidence.

---

# Error Handling

If AI cannot answer confidently

State uncertainty.

Explain why.

Suggest next steps.

Never fabricate certainty.

---

# Office Behaviour

Office should visualize collaboration.

Agents should

Work

Review

Wait

Coordinate

Escalate

Validate

Movement should reflect real execution whenever technically possible.

---

# Blueprint Behaviour

Blueprint should reveal

Relationships

Dependencies

Decision paths

Artifact flow

AI should help explain the graph.

Not dominate it.

---

# Studio Behaviour

Studio should feel like collaborative editing.

AI should improve

Sentences

Logic

Structure

Clarity

Completeness

Without taking ownership away from users.

---

# Desk Behaviour

Desk should prioritize understanding.

AI summarizes.

Explains.

Cross-references.

Highlights inconsistencies.

Suggests improvements.

---

# Mission Control Behaviour

AI should monitor

Health

Risk

Blocked stages

Execution quality

Agent coordination

Not merely display metrics.

---

# AI Quality Checklist

Before approving any AI feature ask

[ ] Does AI improve thinking?

[ ] Does AI explain itself?

[ ] Is confidence justified?

[ ] Can users reject recommendations?

[ ] Is AI context-aware?

[ ] Does AI feel collaborative?

[ ] Does AI avoid unnecessary interruptions?

---

# Non-Negotiables

Never present AI as infallible.

Never hide reasoning.

Never generate recommendations without evidence.

Never interrupt productive work.

Never replace human decision-making.

AI exists to augment expert thinking.
