# Purpose

Composition defines how information is arranged.

Good composition allows users to understand the interface before reading text.

Users should immediately understand:

- Where they are
- What they are doing
- What matters most
- What action comes next

Composition should reduce thinking, not increase it.

---

# Composition Principles

## Principle 1

One Primary Focus

Every screen must have exactly ONE dominant area.

Examples

Studio

Primary

Document Workspace

Office

Primary

Live Agent Workspace

Desk

Primary

Artifact Reader

Blueprint

Primary

Lifecycle Visualization

Never create two competing focal areas.

---

## Principle 2

Progressive Disclosure

Do not expose everything immediately.

Instead

Primary

↓

Secondary

↓

Advanced

↓

Debug

The interface should become more detailed only as users interact.

---

## Principle 3

Three-Zone Layout

Whenever possible, screens should follow:

Navigation

↓

Workspace

↓

Context

Example

LEFT

Navigation

CENTER

Main Work

RIGHT

Context

Assistant

Metadata

History

Review

This pattern should become familiar across IdeaGate.

---

## Principle 4

Reading Direction

The eye should naturally move

Top Left

↓

Center

↓

Right

↓

Bottom

Avoid layouts that force users to search randomly.

---

## Principle 5

Whitespace is Functional

Whitespace is not decoration.

Whitespace creates:

- grouping
- hierarchy
- focus
- rhythm

Never fill empty space simply because it exists.

---

## Principle 6

Every Screen Has One Story

Users should understand the story.

Example

Studio

"I'm improving an artifact."

Office

"My AI team is working."

Desk

"I'm reading and reviewing."

Blueprint

"I'm understanding the system."

Mission Control

"I'm monitoring progress."

Never mix multiple stories on one screen.

---

# Layout Hierarchy

Each screen should contain:

Level 1

Primary Workspace

Level 2

Supporting Panels

Level 3

Context Panels

Level 4

Utilities

Utilities should never visually compete with primary work.

---

# Panel Strategy

Panels exist for context.

Panels should never dominate.

Panels should visually support the workspace.

Avoid:

- oversized sidebars
- oversized inspectors
- unnecessary floating panels

---

# Density

Aim for medium density.

Too sparse feels unfinished.

Too dense feels enterprise-heavy.

The ideal experience is calm without wasting space.

---

# Visual Balance

Balance should come from

- spacing
- alignment
- rhythm
- scale

Never rely on random decoration.

---

# Future Expansion

All screens must allow future additions without redesigning the layout.

Examples

Studio

Future Collaboration

Future AI Review

Future Version Compare

Future Connectors

Future Multi-Agent Editing

Office

Future Departments

Future Team Rooms

Future Live Presence

Future Notifications

Mission Control

Future Metrics

Future Cost Dashboard

Future Health Monitoring

The composition should absorb future capabilities gracefully.

---

# Composition Quality Checklist

Before approving any screen ask:

[ ] Can I identify the primary workspace within 2 seconds?

[ ] Is there only one dominant focus?

[ ] Do panels support rather than compete?

[ ] Does the reading order feel natural?

[ ] Can future features be added without breaking the layout?

[ ] Does the screen feel calm?

[ ] Does the screen resemble premium SaaS rather than an admin dashboard?

---

# Non-Negotiables

Never create layouts that require users to search for their next action.

Never sacrifice clarity for visual novelty.

Never add UI simply because there is available space.

Composition exists to support thinking.
