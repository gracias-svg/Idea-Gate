# Purpose

Typography is the voice of IdeaGate.

Users should feel they are reading a carefully designed product operating system rather than an AI chat application or an enterprise dashboard.

Typography should reduce cognitive effort while increasing confidence.

---

# Design Philosophy

Typography should feel

- calm
- editorial
- modern
- precise
- trustworthy
- effortless

Avoid typography that feels

- playful
- decorative
- futuristic for the sake of being futuristic
- corporate
- noisy
- compressed
- gamer-oriented

---

# Typography Principles

## Principle 1

Hierarchy before decoration.

Users should understand information priority without relying on color.

Size, weight and spacing should communicate importance.

---

## Principle 2

Every text element has a purpose.

Never create text simply to fill space.

Every label, heading and description should justify its existence.

---

## Principle 3

Consistency creates trust.

Users should never wonder

"Why is this heading different?"

Every screen should use the same visual language.

---

# Font Strategy

IdeaGate should have one primary typeface.

Avoid mixing unrelated font families.

Different weights should provide variety.

Not different fonts.

# Heading Strategy

Every screen should have

One H1

Multiple H2

Supporting H3

Avoid unnecessary heading levels.

---

# Information Density

Long documents

Increase line height.

Reduce width.

Dashboards

Reduce line height slightly.

Increase scan speed.

Editors

Prioritize reading comfort.

Mission Control

Prioritize quick recognition.

# Tables

Tables should emphasize readability.

Avoid excessive borders.

Rows should breathe.

Headers should clearly separate from content.

---

# Lists

Lists communicate sequence.

Bullets communicate grouping.

Avoid long unstructured paragraphs.

---

# Empty States

Typography should reassure.

Example

No references added yet.

Upload research or connect an external source.

Avoid

Nothing here.

Empty.

---

# Error Messages

Errors should explain

What happened

Why

What users can do next

Never expose technical implementation details unless inside developer tools.

---

# Success Messages

Keep short.

Avoid celebration.

Good

Artifact updated successfully.

Bad

Awesome!

Everything worked perfectly!

# Accessibility

Maintain sufficient contrast.

Support zoom.

Avoid extremely small labels.

Readable code.

Readable tables.

Comfortable reading sessions longer than 30 minutes.

---

# Typography Quality Checklist

Before approving typography ask

[ ] Can users identify hierarchy within three seconds?

[ ] Does typography reduce cognitive load?

[ ] Are large documents comfortable to read?

[ ] Are labels meaningful?

[ ] Do numbers stand out appropriately?

[ ] Does AI content feel conversational?

[ ] Does the interface resemble premium SaaS?

---

# Non-Negotiables

Never use typography as decoration.

Never create visual hierarchy using color alone.

Never introduce additional font families without strong justification.

Typography should always improve understanding.
